# DX747

DX747 is custom firmware for the M-VAVE FM-1 that turns it into a multitimbral DX7
sound module of up to eight parts, each of which can layer several DX7 voices,
played and controlled from outside over MIDI. It is not a sequencer, a drum machine
or a sampler: the stock sequencer, sampler and non-DX7 sound sources are gone from
the user interface.

It is built on the open FM-1 SDK ([m-vave/fm1_open](https://github.com/m-vave/fm1_open),
base commit `4c7496d`). The sound engine is the SDK's sealed DX7 engine; everything
else (MIDI routing, scenes, screens, the master filter, the button light) is code
in this repository. DX747 is a fork of M-VAVE's open firmware (`FM1_OFFICIAL_OPEN`) and has its
own identity: the firmware package is **`FM1_DX747.fwsc`**, the flashing page **`FM1-DX747.html`**,
the release label **V01** and the update identity **`FM-1_8747747`**.

**Status.** The parts, routing, screens, scenes, SysEx, BRIGHT and filter logic have been run
in the simulator and in host tests, and the firmware builds and passes the SDK's
checks. The Bluetooth and USB audio paths are only checked by reading the code.
**Nothing has been run on a real FM-1 yet.** Read [docs/ON-DEVICE-CHECKLIST.md](docs/ON-DEVICE-CHECKLIST.md) for what
still has to be proven on hardware, and
[docs/FLASHING-AND-RECOVERY.md](docs/FLASHING-AND-RECOVERY.md) before flashing.

## The idea

Eight DX7 engines, one mixer, one set of effects, and on top of them **parts**. The
design and its reasons are in [docs/design/PARTS-MODEL.md](docs/design/PARTS-MODEL.md).

- A **part** is one MIDI channel with one sound. There are up to eight, each on its
  own channel (1 to 16). Part 1 is the unit you think in: "the piano on channel 1".
- A part's **sound** is one to eight **layers**. A layer is one DX7 voice on one
  engine, with its own note window, velocity window, octave shift and fold, level,
  pan, reverb send, delay send, BRIGHT, voice limit and mute. A part with a single
  voice has one layer.
- A part has a **level** that scales all its layers (CC7 on its channel sets it); the
  layers' own levels are the balance inside the part.
- **Engines are the only limit.** Every layer takes one of the eight engines, so
  eight single-layer parts, or one part of eight layers, or anything in between.
  The header shows `ENGINES n/8` (layers in use) and `VOICES n/16`.

From this you get everything with no extra modes:

- **Several keyboards or sequencer tracks:** give each its own part and channel.
- **One keyboard, several sounds:** put several layers in one part with different
  note windows for a split, the same window for a layer, or different velocity
  windows for a sound that changes with how hard you play.
- **A split with an octave change:** give a layer a window and a shift.

A fresh unit has eight single-layer parts on channels 1 to 8 (part 1 on channel 1,
and so on), so a sequencer can use all eight at once. To layer, free an engine first
(remove a part) and add a layer to another part.

The built-in keyboard always plays the **selected part**, on every screen (it plays
the whole part: layers, splits and shifts included). Select another part with
**SELECT**. The selected part is framed on the Parts screen and shown on every
screen that works on a part. If the selected part is an empty slot, the keys play
nothing.

Sixteen voices are shared between all engines. A note on a part with n layers uses n
voices. When the voices run out the oldest note is taken.

## The screens

| Button | Screen |
|---|---|
| **HOME** | Parts: the overview, one row per part. Press again: the selected part in detail (below). |
| **SEQ** | Part: the layers of the selected part. |
| **EDIT** | The framed layer: Sound, then Range, then Velocity, then Sends. Press again for the next. |
| **REC** | MIDI in: the last messages, with which port and channel they came on. |
| **SEL** | Mix: level faders, meters, pan, mute and solo for all eight parts. |
| **FX** | Effects, shared reverb and delay. Press again for the Master filter. |
| **PLAY** | Scenes. |
| **GLO** | System. |
| **SAVE** | Save a scene. |
| **ARP** | LEARN (below). |
| **OCT-**, **OCT+** | Step back and forward: the pages of the layer screens (Sound, Range, Velocity, Sends), FX and the filter, the banks on Scenes, the rows on System, the part on Mix and in detail. On Parts, Part and MIDI in: shift the built-in keyboard by up to two octaves. |
| **ENV**, **LFO** | Add and remove (below). On Mix: mute and solo the selected part. On Scenes: previous and next scene. |
| **EDIT** on Mix | The white keys mute and solo (below). |
| hold **PLAY**, press **OCT-** or **OCT+** | Recall the previous or next stored scene, on any screen. |
| hold **HOME**, press **PLAY** | Stop every note. The screen stays as it was, with its mute/solo or LEARN mode. |

The buttons keep their stock labels; the table above is the map. Holding **ENV** and
**LFO** together while switching on starts safe boot (see below).

**Encoders.** **SELECT** picks the part on every screen that works on a part. **ALGO**
picks the layer inside the part (the framed one). **PRESETS** chooses the patch (1 to
128) of the framed layer on every screen that shows a part (Parts, Part, in detail) and
on every one of the four layer pages. **K1** to **K4** change what the screen's tiles show.

**Text.** Small text is a 5x7 pixel font with softened corners and diagonals (straight strokes stay full
brightness). Larger text (names, numbers, headings) is
drawn from outlines at the screen's own resolution with soft edges, not as magnified
pixels. Everything you need to read is white; only the counters in the header, the
octave numbers on rulers and similar guides are dimmed.

**The overlay.** Every knob turn, and every message ("LAYER ADDED", "NO FREE ENGINE"),
shows a box at the bottom of the screen for a moment: what it is (part 3, layer 2 level)
in small letters and the new value large, with a bar where the value has a range. It
follows the knob for about a second after the last click. Part and layer numbers are
the part's slot (1 to 8) and the layer's place in it; the MIDI channel is always written
`CH n`, so the two are never mistaken for each other.

**The built-in keys play the selected part on every screen**, through the router,
at velocity 100. There are two exceptions. On the Scenes screen the 16 white keys
(numbered 1 to 16 from the left) recall scenes instead; the black keys still play. On Mix,
after **EDIT**, the 16 white keys mute and solo parts and the black keys do nothing (below).
On Scenes while a scene is being named or the flash setup is asked, the keys do nothing.

- **Parts:** eight rows, always the same layout: the part number in a coloured chip (the
  MIDI channel is written `CH n` under the name), the
  name the part was given in the workbench (its first ten letters) or, without one, the
  voice of its main layer (the one that plays the most keys, the first of
  equals), at one size, a small bar of the layers over the keyboard (splits side by
  side, layers stacked, every other layer in a darker tone, a shift as an amber end),
  and `+n` for the other layers. The selected part is framed and names its other
  layers after its channel. A part that is sounding shows an amber dot. **ENV** adds a
  layer to the selected part, or makes a part in an empty slot (on the lowest free
  channel). **LFO** removes the framed layer; the last layer takes the part with it.
  **K1** sets the selected part's volume.
- **Part in detail** (**HOME** a second time, or **HOME** again to go back): one line per
  layer over a keyboard ruler (C0 to C8, middle C marked): the layer's sound, its keys as
  a bar, an octave shift as a small amber tag beside it (`+1`, `-2`), its level, its pan if
  it is off centre and its velocity window if it is narrowed. The part's number, **MIDI
  channel** (**K3**) and **part level** (**K2**, the mixer volume) are the large figures at
  the top; **K1** sets the framed layer's own level, **PRESETS** its patch, **ALGO** frames a layer, **OCT-** and
  **OCT+** step to the previous and next part, **ARP** learns the framed layer's keys.
  Up to three layers get roomy lines, more are packed.
- **Part:** the layers of the selected part with their windows, shifts and velocity
  windows. **ALGO** frames a layer; the framed layer is the one that takes DX7 SysEx.
  **K1** moves the part to the next channel no other part uses, **K2** sets the
  part level. **ENV** and **LFO** add and remove layers.
- **Sound:** **K1** the framed layer's level (its volume inside the part), **K2** the
  pan, **K3** BRIGHT; **PRESETS** chooses its patch 1 to 128 (as on every page).
- **Range:** the framed layer's lowest note (**K1**), highest note (**K2**), octave
  shift (**K3**) and fold (**K4**). The channel is the part's.
- **Velocity:** the framed layer's lowest (**K1**) and highest (**K2**) velocity, with
  all the layers' windows drawn under each other. Use it to split layers by touch.
- **Sends:** reverb send (**K1**), delay send (**K2**), max voices (**K3**).
- **Mix:** one column per part, with its MIDI channel (`CH n`) under the number. Every
  knob works on the whole part: **K1** sets the part level (the fader, CC7), **K2** the
  pan, **K3** the reverb send and **K4** the delay send of all its layers together
  (layers that were set apart stay apart; the pan marker moves with the knob, and shows
  the spread when the layers differ), and **ALGO** moves the part to the next free MIDI
  channel. **OCT-** and **OCT+** step the selected part left and right.
  **ENV** mutes the selected part and **LFO** solos it. A muted part has a filled red M, a
  soloed one a filled amber S, and parts silenced by someone else's solo are dimmed.
  Solo is not saved in scenes.
  **EDIT** turns the white keys into the mute and solo keys: key 1 is part 1's mute,
  key 2 its solo, key 3 part 2's mute and so on, in the order the columns show them,
  and touching a part's key selects the part. The key lamps say what is possible: dark
  for a part that is not there, dim for a key that could be pressed, bright for a part
  that is muted or soloed. The black keys do nothing and go dark in this mode. **EDIT** again, or leaving the screen,
  gives the keys back to playing.
- **Scenes:** white key n recalls scene n of the bank on screen. **OCT-** and **OCT+**
  change the bank (the tabs A to D, 16 scenes each). **ENV** and **LFO** step to the previous
  and next stored scene and recall it.
- **FX** and **Master filter** are two pages (tabs at the top right): **FX** again or
  **OCT-** and **OCT+** switch between them.
- **System:** **SELECT** or **OCT-** and **OCT+** pick a row, **K1** changes it. The **scene channel** row is
  Off or 1 to 16 (below).

**LEARN** sets a note window by playing it: press **ARP** on Part or Range, then play
two notes, the lowest and the highest in either order, on the built-in keys (which
are notes while LEARN waits) or from any MIDI keyboard. The window of the framed
layer becomes those two notes.

Note names use the standard convention: MIDI note 60 is C4.

## Patches and importing DX7 ROMs

The 128 patches are four banks of 32: A is patches 1 to 32, B 33 to 64, C 65 to 96,
D 97 to 128. A MIDI program change 0 to 127 on a part's channel selects the same patches (bank 0;
see [docs/MIDI.md](docs/MIDI.md) for what happens to a layered part).

You import a standard DX7 32-voice bank (a 4,104-byte `.syx` file, such as a ROM
cartridge dump) with the **workbench** (the Sounds tab of `DX747-Workbench.html`, or M-VAVE's own page), which writes it into one of the four
banks and checks it by reading it back. You cannot send such a file straight to the
unit from a MIDI program or DAW: the FM-1's MIDI input discards SysEx messages over
1,024 bytes before the firmware sees them. Single voices (163 bytes) can be sent
directly, see [docs/MIDI.md](docs/MIDI.md).

`tools/dx747/sim/try-rom.sh` imports a ROM into the simulator and lists every voice
with its level, to check a file before you load it onto the unit.

Voices with amplitude-modulation sensitivity (the "BC" voices of the DX7 ROMs, such
as "SAX BC") stay completely silent in this engine until some controller message
arrives, after every voice load and every stop. DX747 sends breath fully open
(CC2 = 127) to the engine after those events so the voices play. This has been
checked in the simulator only, not on the sealed engine of a real unit.

## Playing and velocity

A note from MIDI keeps the velocity it arrives with, and every layer that plays
it gets that velocity. The built-in keys have a fixed velocity of 100. A note off
carries no velocity on to the engines. A layer plays a note only when the velocity is
inside its velocity window (1 to 127 unless you narrow it).

## Scenes

A scene stores the eight parts (channel, level, the framed layer and the layers, each with
its voice, windows, shift, fold, voice limit, level, pan, sends, BRIGHT and mute), which part is
selected, the effects, the master filter and a 12-character name. There are 64, in four
banks of 16, on top of the 128 patches. A scene stores a **copy** of the voices, so editing
a patch afterwards never changes an old scene. The last scene used comes back at power-on.

The scene channel, the master control channel, Bluetooth and the button light are device
settings, not part of a scene: recalling a scene leaves them alone.

Each scene has a 4 KB flash sector of its own (64 scenes and the settings, 260 KB), so a
power cut while saving one can never touch another.

**The first time you save a scene, DX747 asks to erase what stands in the way**:
the stock sample bank, because scenes live in the flash that holds it (any other
foreign data in that flash counts too), or an unfinished stock save that is still
waiting in the staging area. The unit asks first ("FIRST SAVE: FLASH SETUP"):
press HOME to cancel. Until you agree, DX747 writes nothing to that flash, not
even settings; scenes that are already stored stay visible, and the claim erases
only what stands in the way, never scenes that are already stored. **DX747 cannot
back the samples up**: it has no sampler, and the workbench's sample commands are
refused while it runs. If the samples matter, save them with the workbench
**before you install DX747**, while the original firmware is still on the unit
(see [docs/FLASHING-AND-RECOVERY.md](docs/FLASHING-AND-RECOVERY.md)).

**Scenes over MIDI.** Set a **scene channel** on the System screen (Off by default, and
remembered across power cycles). A program change on that channel recalls scene n + 1
(0 to 63); an empty slot does nothing. A MIDI Song Select message does the same where
the sealed engine hands it on to the firmware: the simulator does, **the real unit has
not been tried**. Pick a channel no part uses, because a program change on the scene
channel never reaches a part.

## Control from outside

DX7 SysEx edits, the BRIGHT control, the master filter, program change and bank select
and the controller list are in [docs/MIDI.md](docs/MIDI.md). In short:

- Parameter changes and single-voice dumps edit the **framed layer** of the part on
  the device number plus 1 (choose it on the Part screen with ALGO; layer 1 until you do).
- A **program change** on a part's channel picks its sound. On a part with one layer it
  loads that patch. On a part with several layers it replaces them all with that one
  patch, over the whole keyboard (the first layer stays, at its own level, and the
  others go). Bank select (CC0) is remembered per channel; only bank 0, the DX7 patches,
  exists so far, so a program change after another bank is ignored.
- **CC7** on a part's channel is its level, **CC74** or **CC71** moves the BRIGHT of
  all its layers.
- A **master control channel** (System screen) drives the master filter: CC74
  cutoff, CC71 resonance, CC70 type.

## The DX747 workbench (the web page)

`DX747-Workbench.html` is one file with everything in it: the simulator, a configurator for the unit, a test keyboard and the
firmware updater. Open it in Chrome or Edge on a computer (from disk, or from `https://` or `localhost`). It is built by
`./build.sh --package` (Docker and Node, no Python; `tools/dx747/workbench.mjs` makes this page) into `build/official-web/`, next to the
older stock-derived `FM1-DX747.html`, which is kept as a fallback; `./build.sh --web` makes it without firmware in `build/preview/`. The page is made from `web/page/`; the pinned
`sdk/` files are not changed (`sdk/WebUpdate.js` is reused as it is).

**Two targets, one interface.** The buttons at the top choose what the tabs work on: **Simulator** (the firmware compiled to run in the
page, the same code as the unit; its scenes and settings are kept in the browser; it starts with the scene store set up) or **Connect
FM-1 (USB)** (the unit, over Web MIDI with SysEx: allow it, close other MIDI programs). The tabs do not care which; they speak the
configuration protocol of [docs/CONFIG-PROTOCOL.md](docs/CONFIG-PROTOCOL.md). The unit never reports changes on its own, so the page
asks it every 0.4 s: a change made on the panel shows in the page and the other way round.

- **Device:** the simulator's panel: the screen, 14 buttons, 7 encoders (the +/- buttons or the mouse wheel), the master knob and the
  27 keys, with the lamps. Click once to switch the sound on.
- **Configure:** the eight parts and their layers: channel, level and name per part, and per layer the voice, level, pan, BRIGHT,
  reverb and delay, lowest and highest key, octave shift, fold, velocity window, polyphony, mute, solo; add and remove layers and
  parts; a lane per part shows the key ranges. **Play this part** selects the part the keys play and DX7 editors edit. The voice
  lists hold the presets **read from the unit's own library** (banks A to D, 128 names; **Reload presets** reads them again, and a
  layer whose voice is not the library voice of its program, for example one edited over DX7 SysEx, says "Sounding as ..."). Pan,
  BRIGHT and the octave shift slider snap to their centre (double-click goes there; the arrow keys still step off it). The key
  range is picked on a keyboard from C-1 to G9: click or drag to set the **Lowest** or **Highest** key (the switch moves to the
  other end after each pick; a crossing pulls the other end along, as the unit does) and **Reset** selects the whole keyboard. The
  velocity window has a handle at each end (default the full 1 to 127) and polyphony is a 1 to 8 button row.
- **Sounds:** the 128 voices in four banks by name (click one to give it to the framed layer) and DX7 ROM import into a bank.
- **Scenes:** the 64 scenes: names, parts held, recall, save the current setup into a slot, rename, delete.
- **Master and FX:** the master filter, the shared reverb and delay, the scene channel, the master control channel, the button
  light and Bluetooth audio in.
- **Keyboard:** an on-screen piano that is also played from the computer keyboard (Z S X D C V G B H N J M and Q 2 W 3 E R 5 T 6 Y 7 U,
  Up and Down change the octave, Space is the sustain pedal), with a choice of MIDI channel (or the selected part's), of output (the
  simulator, the unit, any Web MIDI port) and of velocity, a panic button, routing of a hardware MIDI keyboard through the chosen
  output, and a monitor.
- **Update:** installs the DX747 firmware that is inside the page, or restores the original V15 firmware (see
  [docs/FLASHING-AND-RECOVERY.md](docs/FLASHING-AND-RECOVERY.md) first).

The simulator's sound is rendered on the page's main thread and sent to the sound card in small blocks, so its latency is higher
than the unit's, and it stutters if the browser throttles a hidden tab. Dim and bright key lamps are shown as different brightness.
The simulator is a test bench for the configurator and for trying DX747 without a unit, not a substitute for the unit.

The M-VAVE-style workbench page (`FM1-DX747.html`) still works with DX747 for voices, as before: its **Projects and
voices** tab reads and writes the four DX7 voice banks and edits single voices. DX747 has no projects: reading the working project
returns an empty one (so the tab unlocks), the sixteen project slots are empty, saving a project or restoring a project file is
refused, and "import track timbre" accepts only DX7 timbres (any other source is refused, so an engine can never turn into a 303,
808 or sampler). The sample commands are refused too. If a bank write is refused while an unfinished stock save is waiting in the
staging area, the page shows only a device error; saving a scene on the unit and agreeing to the flash setup clears it.

## Power-on chords and safe boot

At power-on the screen plays a five second take-off: the 747 rolls in from the right over the DX747 logo, speeds up, rotates and
climbs out of the top left corner, and then the Parts screen follows. A button, key or encoder turn ends it at once (that press does
nothing else).

Two button chords are read once, at power-on, before the screen and the engines
start:

- **Safe boot: hold ENV and LFO** (DX747 gives those two buttons no function
  otherwise) while switching on; other buttons may be down too. DX747 then skips
  every optional start-up step: its own code starts no engines, loads no scenes or
  settings, reads and writes no flash, sets up no Bluetooth, routes no MIDI (notes,
  controllers, DX7 SysEx and the workbench file protocol are all ignored) and
  ignores the buttons and keys; the master volume knob still works. The screen says
  SAFE BOOT and the ENV and LFO lights are on. The sealed engine itself is not
  affected: its USB connection and its firmware-update messages keep working, so a
  unit that misbehaves can still be updated or sent back to V15. Switch off, let go
  of the buttons and switch on again for a normal start. Seeing the chord by mistake
  costs nothing but that screen.
- **ROM updater: hold OCT- and OCT+ only** (no other button, no note key) for
  about 0.4 s while switching on. This calls the SDK's `fm1_device_recovery()`,
  which stages a flag in RAM and resets towards the chip's USB updater. **It has
  never been tried on hardware**; see
  [docs/FLASHING-AND-RECOVERY.md](docs/FLASHING-AND-RECOVERY.md). Safe boot wins
  when both are held.

If the boot recipe cannot start every engine (memory), every screen's header shows the
`ENGINES` count against the engines that came up in amber, for example "ENGINES 3/6".

## Audio and Bluetooth

- A master filter (off, low-pass, high-pass, band-pass) sits on the eight engines' mix.
- **USB audio out** is taken after the master filter and before the master volume
  knob, so the knob does not change what the computer records. It carries only the
  engines: no USB or Bluetooth input comes back out.
- The knob sets the volume of everything you hear. USB audio in and Bluetooth audio
  in are scaled by the knob too, and added to the engines after the filter.
- **Bluetooth:** MIDI works as a peripheral (a phone or computer connects to the
  FM-1). Audio is receive-only (phone or computer to FM-1); the FM-1 cannot send
  audio to a Bluetooth speaker. The FM-1 cannot connect out to a Bluetooth
  keyboard in this version.
- **Button light:** System, BUTTON LIGHT, 0 (dark) to 8. The default is 3. The
  light is dimmed by software in the key-scan interrupt; how it looks and whether
  it flickers is unverified on hardware.

- Windows (the reference route, which makes the flashing page, and the steps to install
  from it; a Mac or Linux builds the same files with `./build.sh`, see below):
  [docs/BUILD-WINDOWS.md](docs/BUILD-WINDOWS.md). Read

- On a Mac or Linux, with Docker and Node and no Windows: `./build.sh --setup` once, then `./build.sh` (firmware and the SDK's

  ([docs/BUILDING.md](docs/BUILDING.md), Option B).
- The large-text font is `app/dx747/vfont.inc`, generated from the glyph outlines in
  `tools/dx747/gen-vfont.py` (`python3 tools/dx747/gen-vfont.py > app/dx747/vfont.inc`).
- Simulator and tests: `tools/dx747/sim/run-recipes.sh` (screens and behaviour),
  and `make test` in each folder under `tools/dx747/host-test/`.

This tree builds with the Linux (Docker) toolchain to 447,432 bytes of the 453,921 allowed,
with a heap of about 226,000 bytes (at least 49,152 is required). Built on Windows and on a Mac (commit `656b37a`), the two
gave the same build identity, a byte-for-byte identical firmware package (`.fwsc`) and a byte-for-byte identical flashing page
(`docs/LINUX-BUILD-BASELINE.md`, `docs/BUILDING.md`); for the earlier commit `2243433` the loadable sections were compared too.

## Not in this version

- Editing envelopes, LFOs and other voice parameters on the unit (change them over
  SysEx or the workbench).
- Connecting out to a Bluetooth keyboard.
- Receiving a 32-voice bank over MIDI.
- Sending audio to Bluetooth speakers (not possible with this SDK).
- A sequencer, drum machine or sampler.

## Planned

[docs/design/PARTS-MODEL.md](docs/design/PARTS-MODEL.md) is the design of the parts. First
build of it, not yet on hardware, leaves these out:

- **A user sound library:** layered sounds saved on their own and picked by bank select
  1 and up, and a SAVE SOUND action. Scenes already carry layered sounds, so a sound can
  be kept by saving a scene.
- **Part names:** parts are named after their main voice. The name field exists in the
  scene format but the screens have no editor for it yet.
- Dropping the lowest layers when a program change needs more engines than are free
  (a program change never needs one: it only ever shrinks a part).
