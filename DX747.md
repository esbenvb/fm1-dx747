# DX747

DX747 is custom firmware for the M-VAVE FM-1 that turns it into an eight-part
multitimbral DX7 sound module, played and controlled from outside over MIDI. It is
not a sequencer, a drum machine or a sampler: the stock sequencer, sampler and
non-DX7 sound sources are gone from the user interface.

It is built on the open FM-1 SDK ([m-vave/fm1_open](https://github.com/m-vave/fm1_open),
base commit `4c7496d`). The sound engine is the SDK's sealed DX7 engine; everything
else (MIDI routing, scenes, screens, the master filter, the button light) is code
in this repository.

**Status.** The routing, screens, scenes, SysEx, BRIGHT and filter logic have been run
in the simulator and in host tests, and the firmware builds and passes the SDK's
checks. The Bluetooth and USB audio paths are only checked by reading the code.
**Nothing has been run on a real FM-1 yet.** Read [docs/ON-DEVICE-CHECKLIST.md](docs/ON-DEVICE-CHECKLIST.md) for what
still has to be proven on hardware, and
[docs/FLASHING-AND-RECOVERY.md](docs/FLASHING-AND-RECOVERY.md) before flashing.

## The idea

Eight DX7 engines, one mixer, one set of effects. **MIDI channels feed engines.**
Each engine has:

- the MIDI channels it plays on (any of 1 to 16, several allowed),
- a note window (lowest and highest note it plays),
- a shift in octaves, and what to do with a note that shifts out of range
  (DROP it, CLIP to the end, or WRAP by octaves),
- a control channel for controllers, program changes and DX7 SysEx edits,
- a limit on how many voices it may use (1 to 8, default 4),
- level, pan, reverb send, delay send, a BRIGHT tone control, and mute.

From this you get everything with no extra modes:

- **Several keyboards:** give each keyboard its own channel and its own engines.
- **One keyboard, several sounds:** put several engines on the same channel with
  different note windows for a split, or the same window for a layer.
- **A split with an octave change:** give an engine a window and a shift.

The built-in keyboard plays like any other keyboard, on a channel you choose
(default 1), on the screens listed under "The screens" below. By default engine 1 plays on channel 1, engine 2 on channel 2, and so
on up to engine 8 on channel 8.

Sixteen voices are shared between all engines. When they run out the oldest note is
taken. The header shows how many are in use.

## The screens

| Button | Screen |
|---|---|
| **HOME** | Setup (overview by channel). Press again for Engines (overview by engine). |
| **SEQ** | Channel: the detail of one channel, best for splits and layers. |
| **EDIT** | The selected engine: Sound, then Plays from, then Sends. Press again for the next. |
| **REC** | MIDI in: the last messages, with which port and channel they came on. |
| **SEL** | Mix: level faders, meters, pan, mute and solo for all eight engines. |
| **FX** | Effects, shared reverb and delay. Press again for the Master filter. |
| **PLAY** | Scenes. |
| **GLO** | System. |
| **SAVE** | Save a scene. |
| **ARP** | LEARN (below). |
| **OCT-**, **OCT+** | Shift the built-in keyboard by up to two octaves. On Scenes: change bank. |
| hold **HOME**, press **PLAY** | Stop every note. |

The buttons keep their stock labels; the table above is the map. **ENV** and
**LFO** do nothing in this firmware.

**What the built-in keys do depends on the screen.** On MIDI in, Effects, Master
and System they play through the router on the keyboard channel. On Sound and
Sends they play the selected engine directly, to try its sound; that ignores the
channel, window, shift and mute. On every other screen they are selectors: the
16 white keys (numbered 1 to 16 from the left) choose or toggle the thing the
screen lists, the black keys do nothing, and the keyboard is silent. To hear a
split or a layer, play it from another screen or from an external keyboard.
Most screens end with a hint line, and Setup, Engines, Channel, Plays from and MIDI
in also show the 16 keys as a strip just above it.

- **Setup:** white key n opens channel n. A channel that is sending notes while no
  engine listens to it is shown as "ACTIVE, NOT ROUTED YET": that is how you find a
  newly connected keyboard. Press its key, then white keys 1 to 8 to give it engines.
- **Channel:** white keys 1 to 8 add an engine to this channel, or remove it if it is
  already there. **K1** picks the engine ("lane") to edit, **K2** its lowest note,
  **K3** its highest note, **K4** its octave shift. **SELECT** changes channel.
- **Plays from:** white keys 1 to 16 switch channels on and off for this engine.
  **K1** to **K4** set low, high, shift and fold.
- **Sound:** **K1** (or **PRESETS**) chooses the patch 1 to 128, **K2** the level,
  **K3** the pan, **K4** BRIGHT. The keyboard plays this engine so you can listen.
- **Sends:** reverb send, delay send, max voices, control channel.
- **Mix:** white keys 1 to 8 mute engines 1 to 8, white keys 9 to 16 solo them. A
  muted engine has a filled red M, a soloed one a filled amber S, and engines silenced
  by someone else's solo are dimmed. **K1** to **K4** change level, pan, reverb send
  and delay send of the selected engine. Solo is not saved in scenes.
- **Scenes:** white key n recalls scene n of the bank on screen. **OCT-** and
  **OCT+** change the bank (A to D, 16 scenes each).
- **System:** **SELECT** picks a row, **K1** changes it. The keyboard channel row
  shows the channel that is active; a scene can set it too.

**LEARN** sets a note window by playing it: press **ARP** on Channel or Plays from,
then play two notes, the lowest and the highest in either order, on the built-in
keys (which are notes while LEARN waits) or from any MIDI keyboard. The window of
the selected engine becomes those two notes.

Note names use the standard convention: MIDI note 60 is C4.

## Patches and importing DX7 ROMs

The 128 patches are four banks of 32: A is patches 1 to 32, B 33 to 64, C 65 to 96,
D 97 to 128. A MIDI program change 0 to 127 selects the same patches.

You import a standard DX7 32-voice bank (a 4,104-byte `.syx` file, such as a ROM
cartridge dump) with the **M-VAVE workbench**, which writes it into one of the four
banks and checks it by reading it back. You cannot send such a file straight to the
unit from a MIDI program or DAW: the FM-1's MIDI input discards SysEx messages over
1,024 bytes before the firmware sees them. Single voices (163 bytes) can be sent
directly, see [docs/MIDI.md](docs/MIDI.md).

`tools/dx747/sim/try-rom.sh` imports a ROM into the simulator and lists every voice
with its level, to check a file before you load it onto the unit.

Voices with amplitude-modulation sensitivity (the "BC" voices of the DX7 ROMs, such
as "SAX BC") stay completely silent in this engine until some controller message
arrives, after every voice load and every stop. DX747 sends breath fully open
(CC2 = 127) to the engine after those events so the voices play. This has been
checked in the simulator only, not on the sealed engine of a real unit.

## Playing and velocity

A note from MIDI keeps the velocity it arrives with, and every engine that plays
it gets that velocity. The built-in keys have a fixed velocity of 100. A note off
carries no velocity on to the engines.

## Scenes

A scene stores all eight engines (voice, play channels, windows, shift, fold,
control channel, voice limit, level, pan, sends, BRIGHT, mute), the effects, the
master filter, the keyboard channel and a 12-character name. There are 64, in four
banks of 16, on top of the 128 patches. The last scene used comes back at power-on.

**The first time you save a scene, DX747 erases the stock sample bank**, because
scenes live in the flash that holds it. The unit asks first ("FIRST SAVE: FLASH
SETUP"): press HOME to cancel. **DX747 cannot back the samples up**: it has no
sampler, and the workbench's sample commands are refused while it runs. If the
samples matter, save them with the workbench **before you install DX747**, while
the original firmware is still on the unit (see
[docs/FLASHING-AND-RECOVERY.md](docs/FLASHING-AND-RECOVERY.md)).

## Control from outside

DX7 SysEx edits, the BRIGHT control, the master filter and the controller list are
in [docs/MIDI.md](docs/MIDI.md). In short:

- Parameter changes and single-voice dumps edit the engine whose control channel is
  the device number plus 1. If none has it, they edit the one engine that plays on
  that channel, but only when no other engine plays there and it has no control
  channel of its own; otherwise nothing happens.
- CC74 or CC71 on an engine's channel moves its BRIGHT: a signed offset added to the
  output level of the modulators, so the sound gets brighter or duller without
  changing the volume.
- A **master control channel** (System screen) drives the master filter: CC74
  cutoff, CC71 resonance, CC70 type.

## Audio and Bluetooth

- A master filter (off, low-pass, high-pass, band-pass) sits on the eight engines' mix.
- **USB audio out** is taken after the master filter and before the master volume
  knob, so the knob does not change what the computer records. It carries only the
  engines: no USB or Bluetooth input comes back out.
- The knob sets the volume of everything you hear. USB audio in and Bluetooth audio
  in are scaled by the knob too, and added to the engines after the filter.
- **Bluetooth:** MIDI works as a peripheral (a phone or computer connects to the
  FM-1). Audio is receive-only (phone or computer to FM-1); the FM-1 cannot send
  audio to a Bluetooth speaker. The FM-1 cannot connect out to a Bluetooth
  keyboard in this version.
- **Button light:** System, BUTTON LIGHT, 0 (dark) to 8. The default is 3. The
  light is dimmed by software in the key-scan interrupt; how it looks and whether
  it flickers is unverified on hardware.

## Building

- Windows (the route that produces the flashing page, the only way to install a
  custom firmware, and the steps to install from it):
  [docs/BUILD-WINDOWS.md](docs/BUILD-WINDOWS.md). Read
  [docs/FLASHING-AND-RECOVERY.md](docs/FLASHING-AND-RECOVERY.md) before installing.
- A quick check on a Mac with Docker (needs Docker Desktop, Node, and the Linux
  toolchain unpacked once, see the same guide):
  `tools/dx747/docker/build.sh -o build/dx747/docker/work .`
- Simulator and tests: `tools/dx747/sim/run-recipes.sh` (screens and behaviour),
  and `make test` in each folder under `tools/dx747/host-test/`.

With JieLi's Linux toolchain this tree builds to about 427,900 bytes of the 453,921
allowed, with a heap of about 237,000 bytes (at least 49,152 is required). The
Windows build, which makes the file you flash, has not been measured.

## Not in this version

- Editing envelopes, LFOs and other voice parameters on the unit (change them over
  SysEx or the workbench).
- Connecting out to a Bluetooth keyboard.
- Receiving a 32-voice bank over MIDI.
- Sending audio to Bluetooth speakers (not possible with this SDK).
- A sequencer, drum machine or sampler.
